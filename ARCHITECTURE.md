## 2. Спецификация ключевых компонентов

### 2.1. Единый интерфейс солвера (`src/solvers/base.py`)
Все солверы обязаны реализовывать базовый абстрактный класс для исключения расхождений в сигнатурах:

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
import numpy as np

@dataclass
class SolverResult:
    assignment: np.ndarray      # Вектор длиной N: assignment[i] = индекс назначенной задачи
    total_cost: float           # Суммарная стоимость решения
    execution_time_ms: float    # Время выполнения алгоритма в миллисекундах
    is_feasible: bool           # Флаг корректности (нет ли дубликатов)

class BaseSolver(ABC):
    @abstractmethod
    def solve(self, cost_matrix: np.ndarray) -> SolverResult:
        """Решает задачу для одной матрицы (N, N)."""
        pass

    def solve_batch(self, cost_matrices: np.ndarray) -> list[SolverResult]:
        """Решает задачу для батча матриц (B, N, N). По умолчанию - последовательный вызов."""
        return [self.solve(matrix) for matrix in cost_matrices]
```

### 2.2. Нейросетевой пайплайн (`src/models/`)

Пайплайн состоит из трех строго разделенных шагов:

```
[Матрица C (B, N, N)] 
        │
        ▼
┌────────────────────────────────────────┐
│ 1. Edge-MLP Encoder                    │
│    - Вычисление row_mean и col_mean    │
│    - Конкатенация признаков: (C, r, c) │
│    - Полносвязные слои 1x1             │
└────────────────────────────────────────┘
        │ Логиты S (B, N, N)
        ▼
┌────────────────────────────────────────┐
│ 2. Sinkhorn Layer                      │
│    - Температурное масштабирование     │
│    - L итераций нормализации строк/кол │
└────────────────────────────────────────┘
        │ Квази-дважды стохастическая матрица P (B, N, N)
        ▼
┌────────────────────────────────────────┐
│ 3. Greedy Rounding Decoder             │
│    - Векторизованный жадный выбор      │
│    - Устранение коллизий               │
└────────────────────────────────────────┘
        │
        ▼
[Бинарная матрица перестановок X (B, N, N)]
```

#### Архитектурная особенность Edge-MLP:
Модель не зависит от $N$, так как работает с каждым ребром $(i, j)$ локально, обогащая его глобальным контекстом строки и столбца:
$$h_{ij} = \left[ C_{ij}, \; \frac{1}{N}\sum_{k=1}^N C_{ik}, \; \frac{1}{N}\sum_{m=1}^N C_{mj} \right] \in \mathbb{R}^3$$
Вектор $h_{ij}$ пропускается через MLP ($3 \to 32 \to 32 \to 1$). За счет этого модель обучается один раз, а применяется к матрицам любого размера.

### 2.3. Модуль бенчмаркинга (`src/benchmark/timer.py`)

Для исключения погрешностей измерений замеряется чистая вычислительная работа:
- **Для CPU (OR-Tools, SciPy):** `time.perf_counter_ns()`.
- **Для GPU (PyTorch):** `torch.cuda.Event(enable_timing=True)`. Использование `time.time()` на GPU строго запрещено, так как оно фиксирует лишь асинхронную постановку кернела в очередь драйвера.

## 3. Рекомендуемый гибридный паттерн (Hybrid Fallback Architecture)

В качестве архитектурного вывода работы предлагается шаблон микросервиса диспетчеризации:

```
Запрос на назначение (Матрица C, SLA: T_max)
                      │
                      ▼
            Размерность N > N_threshold?
                   /        \
              ДА  /          \  НЕТ
                 ▼            ▼
     [Нейросетевой солвер]   [OR-Tools Солвер]
     - Гарантированный SLA   - 100% математический оптимум
     - Субоптимальность ~3-7%
                 \            /
                  ▼          ▼
            Итоговое назначение исполнителей
```
