## 1. Цель и назначение проекта
**Цель работы:** Исследование границы применимости точных алгоритмов дискретной оптимизации и суррогатных нейросетевых моделей для задачи о назначениях (LSAP), оценка компромисса «скорость вычислений против потери оптимальности» (latency vs optimality gap) и разработка рекомендаций по архитектуре высоконагруженных диспетчерских микросервисов.

**Назначение системы:** Программный комплекс для генерации тестовых наборов данных, запуска бенчмарков алгоритмов распределения ресурсов, сбора телеметрии и построения аналитических отчетов.

## 2. Требования к функциональным модулям

### 2.1. Модуль генерации данных (`data_generator`)
Модуль должен формировать матрицы затрат $C \in \mathbb{R}^{N \times N}$ со следующими характеристиками:
1. **Размерности задач ($N$):** $N \in \{10, 25, 50, 100, 250, 500, 1000\}$.
2. **Типы распределений:**
   - `Uniform`: равномерное распределение $U(0, 1)$ (базовый синтетический стресс-тест без пространственных корреляций).
   - `Lognormal`: логнормальное распределение $\mu=0, \sigma=0.75$ (моделирование трудозатрат с «длинным хвостом» сложных задач).
   - `Metric2D`: евклидовы расстояния между $N$ случайными точками исполнителей и $N$ точками задач на плоскости $[0, 1] \times [0, 1]$ (эмуляция курьерской доставки / выезда специалистов в городе).
3. **Режимы генерации:**
   - Одиночные матрицы для замера задержки (Latency).
   - Батчи матриц размера $B \in \{16, 64, 128\}$ для замера пропускной способности (Throughput).
4. **Воспроизводимость:** фиксация `seed` для генераторов псевдослучайных чисел (`numpy.random`, `torch.manual_seed`).

### 2.2. Модуль точных алгоритмов (`solvers/classical`)
1. **Kuhn-Munkres (Венгерский алгоритм):**
   - Реализация на базе оптимизированной C-библиотеки `scipy.optimize.linear_sum_assignment`.
   - Временная сложность: $O(N^3)$.
2. **Google OR-Tools Solver:**
   - Реализация на базе C++ компонента `ortools.graph.python.linear_sum_assignment.SimpleLinearSumAssignment`.
   - Назначение: базовый золотой стандарт (Ground Truth) глобального оптимума $Cost_{opt}$.
3. **Единый интерфейс солвера:**
   - Вход: матрица $C$ размерности $(N, N)$.
   - Выход: вектор назначений $\mathbf{y} \in \mathbb{Z}^N$ (где $y_i = j$), бинарная матрица $X \in \{0, 1\}^{N \times N}$ и скаляр общей стоимости $\sum C_{ij} X_{ij}$.

### 2.3. Модуль нейросетевого аппроксиматора (`solvers/neural`)
1. **Архитектура модели:**
   - Архитектура **Edge-MLP / Transformer-like**, инвариантная к размерности $N$. Сеть должна обрабатывать матрицу любого размера без переобучения входного слоя.
   - Слой дифференцируемой нормализации **Sinkhorn Layer** (параметры: число итераций $L \in [10, 30]$, температура $\tau \in [0.05, 0.2]$).
2. **Модуль жадного округления (Greedy Rounding Decoder):**
   - Проекция непрерывной квази-дважды стохастической матрицы вероятностей $P \in \mathcal{B}_N$ в строго допустимую матрицу перестановок $X \in \mathcal{P}_N$.
   - Алгоритмическая сложность декодера: не хуже $O(N^2 \log N)$, векторизованная реализация без медленных интерпретируемых циклов Python.
3. **Пайплайн обучения:**
   - Поддержка обучения с учителем (Supervised Learning на ответах OR-Tools с функцией потерь Cross-Entropy).
   - Функция потерь с бинарной регуляризацией для выталкивания вероятностей к границам политопа.

### 2.4. Модуль бенчмаркинга и метрик (`benchmark`)
1. **Протокол замеров времени:**
   - Обязательный этап «прогрева» (Warm-up) не менее 5 итераций для исключения времени инициализации CUDA / кэшей процессора.
   - Синхронизация GPU потоков через `torch.cuda.synchronize()` до и после инференса.
   - Раздельный зачет времени:
     - Чистый инференс нейросети ($T_{NN}$).
     - Время жадного декодирования ($T_{decode}$).
     - Время передачи данных Host $\to$ Device $\to$ Host ($T_{transfer}$).
2. **Вычисляемые метрики:**
   - **Optimality Gap ($\Delta$):**
     $$\Delta = \frac{Cost_{NN} - Cost_{Opt}}{Cost_{Opt}} \times 100\%$$
   - **Допустимость решений (Feasibility Rate):** проверка условий $\sum_i X_{ij} = 1$ и $\sum_j X_{ij} = 1$.
   - **Latency (мс):** среднее время построения одного решения и перцентили p95, p99.
   - **Throughput (задач/сек):** количество обработанных матриц в секунду в пакетном режиме (Batch mode).

### 2.5. Модуль визуализации и отчетов (`visualization`)
- Экспорт результатов в форматы `.csv` и `.json`.
- Автоматическая генерация графиков (Matplotlib/Seaborn):
  1. Кривая масштабирования времени: $\log(T)$ от $N$.
  2. Точка перегиба (Cross-over point), где нейросеть начинает опережать точный алгоритм.
  3. Зависимость Optimality Gap от размерности $N$ и типа распределения.
  4. Сравнительная диаграмма пропускной способности при пакетной обработке (Batching Speedup).

- **Язык программирования:** Python 3.10+
- **Библиотеки оптимизации:** `ortools` (>= 9.8), `scipy` (>= 1.11)
- **Библиотеки машинного обучения:** `torch` (>= 2.1)
- **Обработка данных и вычисления:** `numpy`, `pandas`
- **Визуализация:** `matplotlib`, `seaborn`
- **Аппаратные требования:** CPU x86-64, GPU с поддержкой CUDA (рекомендуется для демонстрации преимуществ батчинга, но код обязан работать и на CPU fallback).
